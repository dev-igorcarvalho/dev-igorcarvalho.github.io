Design System

One stylesheet, two themes, and an "engineering preprint" anatomy

Format · a single centralized assets/style.css

Summary

Every page on this site — the shell and every article fragment — obeys one stylesheet. There is no per-article CSS beyond an occasional inline style="" for a one-off tweak. This page documents the two color themes and the typographic anatomy that every dense article follows.

1. Palette — "Onsen"

Two themes share the same warm, hot-spring-inspired palette: Onsen Day (light) leans into a linen-toned paper with terracotta accents, and Onsen Night (dark) mirrors it in deep warm browns. Both are defined as CSS custom properties — --desk, --paper, --ink, --muted, --rule, --accent, --danger, --warn, --code-bg, --code-rule, --shadow — so any new color in CSS or inline SVG has to reuse one of these variables rather than hardcoding a hex value. Contrast against text is checked with the WCAG relative-luminance formula every time a color changes, not assumed.

2. Typography

Body text and headings use a serif (Charter, falling back through Georgia to Times New Roman); code, the sidebar, and running heads use a system monospace stack. The scale is driven from a single root font-size that steps up across three breakpoints (mobile/tablet/desktop) — since nearly everything else on the page is sized in rem, the whole site's type, spacing, and sidebar scale together from that one value.

3. Article anatomy

Dense articles share a fixed set of classes modeled on an arXiv preprint: .sheet (the card), .stamp (the vertical rotated label), .running-head, header.titleblock (title, subtitle, author, meta), section.abstract, numbered h2/h3, figure.listing for code, figure.fig for diagrams, and footer.colophon for the closing byline. Sections with children — like this one — additionally get a JS-rendered "In this section" list and a pager, both computed from that section's manifest.json rather than hand-typed.
