Site Architecture

A static site with no build step, no framework, and no excuse to be slow

Format · HTML + CSS + vanilla JS · Hosting: GitHub Pages

Summary

This site is a deliberately simple engineering experiment: every page is an isolated HTML fragment, fetched on demand and injected into a single shell page. There's no bundler, no node_modules, no build step — just static files the browser already understands. The result is a "book" where every sidebar tab is a chapter, loaded in milliseconds and addressable by URL.

1. Why this shape exists

Most static-site generators solve a problem this site doesn't have: thousands of pages, taxonomies, RSS, full-text search. Here the goal is different — a handful of technical articles, published with git push and nothing else. A build framework for that would be a truck to buy bread.

The architecture is as direct as it gets: index.html is the shell (sidebar + content area); every article lives as its own folder under /articles/<slug>/, with an index.html entry point and a manifest.json describing its children (if any); a vanilla-JS router fetches the right fragment and injects it into the shell, syncing the URL hash so the browser's back button and a hard refresh both keep working.

2. Sections and sub-sections

Every top-level entry in the sidebar is a folder with an index.html and a manifest.json. When that manifest is empty, the folder is a single flat article — nothing else is rendered. When it lists entries, those entries must be real files living in that same folder's own assets/ directory; a section's manifest is never allowed to point outside its own folder. This page is itself an example: it's a child of the Contents section, fetched from articles/contents/assets/site-architecture.html, listed in articles/contents/manifest.json.

3. Navigation

Two independent navigation layers exist side by side: a site-wide "next/back" pager (driven by articles/sequence.json) chains together the top-level sections in reading order, while a per-section pager cycles between siblings within the same folder using that folder's own manifest.json. Every child page also carries a link back up to the site's root Contents page, so you're never more than one click from the index no matter how deep you are.
